## Bağlam

Kalibrasyon adımında (Adım 3) operatör aracın teker temas noktalarını işaretleyip ardından
birkaç kare ilerleterek arka tekerin ön tekerin eski konumuna gelmesini bekler. Bu, araç boyunu
(wheelbase) boyuna referans olarak kullanmanın doğal yoludur.

Problem: Kare ayrıklığı nedeniyle arka teker hiçbir zaman hedef konuma **tam** düşmez — ya
bir kare önde ya bir kare geride kalır. Yanlış hizalama → yanlış dünya koordinatı → hız
hatasına dönüşür.

Mevcut `src/speed/axle_stepping.py` (T8) aynı alt-kare enterpolasyonu hız ölçümü için yapıyor.
Bu görev aynı prensibi **kalibrasyon kontrol noktası ekleme** akışına taşır.

## Kapsam

**İçinde:**
- Adım 3 (kontrol noktaları) UI'ında "alt-kare enterpolasyon" modu: operatör hedef noktayı
  bracketing iki karede işaretler, sistem ara konumu hesaplar.
- Ghost overlay: daha önce işaretlenen ön teker konumunu "hedef" olarak mevcut karedeki
  canvas üzerine yarı saydam çizer.
- Enterpolasyon mantığı Python tarafında (hesap backend'de kalır, forensic iz oluşur).
- Yeni kalibrasyon noktası tipi: `"interpolated"` — audit trail'de hangi noktaların
  enterpolasyondan türediği işaretli olur.

**Dışında:**
- Otomatik teker tespiti (CV ile) — operatör tıklamaya devam eder.
- Hız ölçüm akışında değişiklik yok (T8 dokunulmaz).

## Teknik Analiz

### Enterpolasyon Formülü

```
Frame N:   teker  →  (x_n,  y_n)    [hedefin gerisinde]
Frame N+1: teker  →  (x_n1, y_n1)   [hedefin önünde]
Hedef: (x_target, y_target)          [önceki ön teker konumu]

İlerleme yönüne göre hedef ekseni seçilir (y veya x — harekete en dik olan eksen).
t = (y_target - y_n) / (y_n1 - y_n)
x_interp = x_n + t * (x_n1 - x_n)
Sonuç: (x_interp, y_target)   — piksel-altı hassasiyet
```

### UX Akışı

1. Operatör Frame A'da ön teker kontakt noktasını işaretler (normal gibi).
2. Sistem bu noktayı "ghost target" olarak tutar.
3. Operatör sonraki karelerde ilerler — canvas'ta ghost overlay görünür (kırmızı/turuncu
   yarı saydam daire veya crosshair).
4. Arka teker ghost'a yaklaştığında operatör **iki komşu karede** (biri önce, biri sonra)
   teker konumunu işaretler.
5. "Enterpolasyonu Hesapla" düğmesi veya otomatik tetik: t hesaplanır, ara nokta üretilir.
6. Canvas üretilen noktayı gösterir (farklı renkle — yeşil?). Operatör onaylar veya reddeder.

### Etkilenen Dosyalar

- `frontend/src/components/CalibrationCanvas.tsx` — ghost overlay state + iki-kare
  işaretleme modu UI
- `frontend/src/steps/CalibrationStep.tsx` (veya benzeri) — mevcut adım bileşeni
- `src/calibration/homography.py` — kontrol noktası yapısına `"interpolated": bool` alanı
- `src/ui/app.py` — enterpolasyon hesabı için yeni endpoint veya mevcut calibrate'e parametre
- `tests/test_calibration_interpolation.py` — yeni birim testler

### Seçilen Yaklaşım

Ghost overlay + iki-kare manuel işaret → backend enterpolasyon → operatör onayı.

Otomatik teker tespiti kapsam dışı (CLAUDE.md §5: "kara kutu yok, operatör onayı şart").
Enterpolasyonun log'a "interpolated=true" yazılması forensic izlenebilirlik sağlar.

## Uygulama Planı

1. Backend: `interpolate_calibration_point(frame_n_px, frame_n1_px, target_px)` util
   fonksiyonu + birim testler.
2. Backend: yeni endpoint `POST /api/video/{video_id}/interpolate-point`
   (body: `frame_n`, `frame_n1`, `target_pixel`, video_id context'ten FPS).
3. Frontend: `CalibrationCanvas`'ta "ghost overlay" state — önceki işaretlenen nokta
   koordinatını bir sonraki kare görüntüsüne bindirme.
4. Frontend: "Bracket mode" — aynı kontrol noktası için iki kare tıklaması alma,
   endpoint'i çağırma, sonucu canvas'a ekleme.
5. Audit: `calibration.json`'a enterpolasyon parametrelerini yaz (frame_n, frame_n1, t).
