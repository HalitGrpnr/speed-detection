## Aks Genişliği Çapraz Doğrulama

### Modül Yerleşimi
```
src/reliability/
  axle_check.py   # suggest_axle_frame, axle_width_m, axle_cross_check
tests/
  test_reliability_axle.py
```

### Veri Modeli ve Fonksiyon İmzaları
```python
# src/reliability/axle_check.py
def suggest_axle_frame(track: Track) -> int | None:
    """Track.points içinde bbox alanı (genişlik×yükseklik) en büyük olan kareyi öner.
    Yalnızca bir sezgisel başlangıç noktası — otomatik doğru kabul edilmez, operatör
    başka bir kare seçebilir. points boşsa None."""

def axle_width_m(
    H: np.ndarray,
    pixel_left: tuple[float, float],
    pixel_right: tuple[float, float],
) -> float:
    """İki piksel noktasını pixel_to_world (src/calibration/homography.py) ile dünya
    düzlemine taşı, öklid mesafesini (metre) döndür."""

def axle_cross_check(
    H: np.ndarray,
    pixel_left: tuple[float, float],
    pixel_right: tuple[float, float],
    known_width_m: float,
) -> dict:
    """{'measured_m': float, 'known_m': float, 'error_pct': float}
    error_pct = abs(measured - known) / known * 100."""
```

### Backend
- `src/ui/schemas.py`: `AxleCheckRequest` (`pixel_left`, `pixel_right`, `known_width_m`),
  `AxleCheckResponse` (`measured_m`, `known_m`, `error_pct`), `AxleSuggestFrameResponse`
  (`frame_n: int | None`).
- `src/ui/app.py`:
  - `GET /api/job/{job_id}/track/{track_id}/axle-suggest-frame` → `suggest_axle_frame` sonucu.
  - `POST /api/job/{job_id}/track/{track_id}/axle-check` → **sunucu-tarafı H'yi job kaydından
    yeniden hesaplar** (istemciden H kabul etmez — R4 kuralıyla tutarlı), `axle_cross_check`
    çağırır, sonucu job kaydına (`job_store`) opsiyonel alan olarak yazar (rapor üretiminde
    kullanılmak üzere).

### Rapor (kapsam daraltıldı — uygulama sırasında ortaya çıkan kısıt)
`generate_report()` tam bir `PipelineResult` nesnesi ister; pipeline tamamlandığında yalnızca
`result_json` (özet tahminler) ve `report.pdf`/`overlay.mp4` kalıcı tutuluyor — tam `PipelineResult`
job thread'i bitince bellekten düşüyor. Aks doğrulaması ise sonuç ekranında, PDF zaten
üretildikten *sonra* yapılıyor. PDF'i yerinde güncellemek (üzerine yazmak) forensic açıdan da
sorunlu: bir raporun operatör aksiyonuyla sessizce değişmesi audit trail'i belirsizleştirir.
**Karar:** v1'de aks doğrulaması PDF'e otomatik eklenmez. Sonuç, `axle-check` endpoint'inin
yanıtında operatöre gösterilir **ve** `out_dir/axle_check_<track_id>.json` olarak zaman damgalı,
kalıcı bir denetim kaydı halinde diske yazılır (bkz. `src/ui/app.py::axle_check`). Bilirkişi
gerekirse bu JSON'u veya ekran görüntüsünü rapora elle ek yapabilir. Tam `PipelineResult`
kalıcılığı + PDF yeniden-üretimi ayrı bir görev olarak bırakıldı (bkz. `PROGRESS.md` açık işler).

### Frontend
- Sonuç ekranı (`frontend/src/features/results/`, M8 Step 7 bileşenleri): araç hız tablosunda
  satır başına opsiyonel "Aks genişliği doğrula" aksiyonu. Önerilen kareyi gösterir, bbox
  köşelerinden ön-dolgulu iki sürüklenebilir nokta + bilinen genişlik input'u; sonucu
  (measured/known/%hata) satırda gösterir. Mevcut route/state yapısını bozmaz.

### Kabul Testleri
1. `axle_width_m`: bilinen basit H (ör. ölçek-only) + bilinen iki piksel noktası → beklenen
   mesafe (metre) ±epsilon.
2. `axle_cross_check`: `measured != known` durumunda `error_pct` doğru hesaplanır;
   `measured == known` → `error_pct == 0`.
3. `suggest_axle_frame`: sentetik `Track` (birkaç `TrackPoint`, farklı bbox boyutları) →
   en büyük bbox alanına sahip `frame` döner.
4. `suggest_axle_frame([])` → `None`.
5. Endpoint testleri (`tests/test_ui_api.py` deseninde): suggest-frame ve axle-check 200 döner,
   şekil doğru; geçersiz `job_id`/`track_id` → 404.
